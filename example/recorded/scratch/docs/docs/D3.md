## 0. Purpose and standards

D3 says how the desk protects the personal data of members. It follows the member data rule PRI-02 (personal data stays local) of D1 and the baseline of a small non-profit service.

## 1. Security decisions

| ID | Decision | Reason |
|---|---|---|
| SEC-A01 | The desk is reachable from the library network only | Volunteers work at the desk, nobody else needs it |

## 2. Assets, actors, trust boundaries and flows

### 2.1 Assets

Member names and phone numbers, and the loan history.

### 2.2 Actors and plausible abuse

A curious visitor at the desk. A volunteer who copies the member list. A lost laptop.

### 2.3 Trust boundaries

| ID | Boundary | Crossing |
|---|---|---|
| TB-1 | The edge of the library network | Only the desk laptop crosses it |

### 2.4 Flows

The desk screen sends a loan to the desk server, which writes it to the data file.

## 3. Amendments

None.

## 4. Cross-cutting requirements

### 4.1 Identity

| ID | Requirement | Verified by |
|---|---|---|
| SEC-ID-01 | A volunteer signs in with a personal code, and a session ends after 15 minutes | Session test |

### 4.2 Cryptography

The connection to the desk uses TLS inside the library network.

### 4.3 Logging

Logs hold no name and no phone number (PRI-02, personal data stays local).

### 4.4 Data

| ID | Requirement | Verified by |
|---|---|---|
| SEC-DAT-01 | Only the name and the phone number of a member are stored | Schema review |

### 4.5 Backup

The data file is copied every night. The copy is restored once on a test machine before 2026-12-28.

### 4.6 Software development lifecycle

Every change goes through a pull request and a green build.

### 4.7 Infrastructure

The server accepts connections from the library network only (SEC-A01, network limit).

## 5. Per-component requirements

### 5.1 Desk server

It refuses a request with no valid session.

## 6. Channels and operational security

No e-mail and no messages are sent in phase 1.

## 7. Coverage matrix

| Requirement | Covered by |
|---|---|
| SEC-ID-01 | Session test |
| SEC-DAT-01 | Schema review |

## 8. Residual risks

A volunteer can still read the member list on the screen. The library accepts this risk.

## 9. Induced backlog items

None.

## 10. Open decisions and accepted risks

None.

## 1. Purpose and reading conventions

This document says what the Fernhill loan desk does. It does not say how: D2 does. Each requirement has an ID and can be answered with done or not done. A value nobody has given yet is marked PROVISIONAL and listed in `intake/provisionals.md`.

## 2. Context, objectives and scope

### 2.1 Context

The Fernhill Tool Library lends tools to about 300 neighbours. Volunteers write each loan on paper at the desk on Saturdays. One tool in ten is lost each year.

### 2.2 Objectives and success indicators

- No tool is lost without a record.
- Every late tool shows in the overdue report on its due day.
- A volunteer registers a loan in under 30 seconds (NFR-01, desk answers fast).

### 2.3 Scope by phase

| Phase | Capability | Target date |
|---|---|---|
| Phase 1 | Desk screen: catalogue, members, loans, returns, late fee, overdue report | 2026-12-28 |
| Phase 2 | Online booking and a public site | not planned |

## 3. Non-negotiable business principles

| ID | Principle | Why it is not negotiable |
|---|---|---|
| PRI-01 | A tool is never lent twice | A tool that is out cannot be on the shelf, so the record must say so |
| PRI-02 | A member's personal data stays on the library's own server | The library promised it to its members |

## 4. Actors, surfaces and roles

### 4.1 Actors and surfaces

| Actor | Surface | Notes |
|---|---|---|
| Volunteer | Desk screen | Uses it on Saturdays, one at a time |
| Chair | Monthly report | Reads, never edits |
| Member | None | Borrows at the desk, has no account |

### 4.2 Roles by module

Volunteers can use every module. The chair can read the overdue report. A member has no access.

## 6. End-to-end journeys

### 6.1 A member borrows a drill

The member brings a drill to the desk. The volunteer finds the member, finds the tool, confirms. The screen shows the due date. The member leaves with the drill.

## 7. Requirements per module

### 7.1 Module CAT: the catalogue

**Situation.** The library has a spreadsheet of about 180 tools.

**Rule.** Each tool has one record, and its record says where it is.

**What it does not do.** It does not take photos or prices.

| ID | Requirement | Priority | Nature | Acceptance |
|---|---|---|---|---|
| FR-CAT-01 | A volunteer can add and find a tool record | MUST | behaviour | A new tool is found by its name |
| FR-CAT-02 | A volunteer can mark a tool as in repair | SHOULD | behaviour | A tool in repair cannot be lent |

### 7.2 Module LND: loans

**Situation.** Loans are on paper today.

**Rule.** A tool is never lent twice (PRI-01, a tool is never lent twice).

**What it does not do.** It does not take payments.

| ID | Requirement | Priority | Nature | Acceptance |
|---|---|---|---|---|
| FR-LND-01 | A volunteer can register a loan of a tool to a member | MUST | behaviour | The loan shows a due date 7 days later (PAR-01, loan length) |
| FR-LND-02 | A volunteer can register the return of a tool | MUST | behaviour | The tool is on the shelf again |
| FR-LND-03 | A late return adds a late fee for each late day | MUST | behaviour | The fee follows PAR-02 (late fee per day) and its cap |

### 7.3 Module MEM: members

**Situation.** Members are on a paper list.

**Rule.** Only the name and the phone number are kept (PRI-02, personal data stays local).

**What it does not do.** It does not send messages.

| ID | Requirement | Priority | Nature | Acceptance |
|---|---|---|---|---|
| FR-MEM-01 | A volunteer can add a member and find a member | MUST | behaviour | A new member is found by name |

### 7.4 Module REP: the overdue report

**Situation.** Late tools are found by chance.

**Rule.** The report lists every tool past its due date.

**What it does not do.** It does not contact the member.

| ID | Requirement | Priority | Nature | Acceptance |
|---|---|---|---|---|
| FR-REP-01 | The chair and the volunteers can list the overdue tools | MUST | behaviour | A tool past its due date is listed with its member |

## 8. Optional sections

### 8.1 Lifecycles

A tool is on the shelf, out, or in repair.

### 8.2 Public API

None.

### 8.3 Compliance

Member data is personal data. D3 says how it is protected.

### 8.4 Migration

The spreadsheet of tools is loaded once into the catalogue (FR-CAT-01, add a tool record).
